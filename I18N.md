# Internationalization

The supported locales are English (`en-IN`) and Hindi (`hi-IN`); use short locale keys `en` and `hi` internally and map them consistently for formatting. Store UI strings in Laravel translation resources under `lang/en` and `lang/hi`. Store dynamic content in explicit bilingual database columns (`title_en`, `title_hi`, `description_en`, `description_hi`, etc.), preserving `utf8mb4` end to end.

Persist the selected locale in session and maintain it through local navigation. Validate locale input against the supported allow-list, set `<html lang>` correctly, and use localized dates/numbers as appropriate. Define deterministic fallback: show the requested locale when present, otherwise the other language, and expose a subtle indication when a fallback is used in admin preview. Do not render blank titles or clip Hindi text.

Use Noto Sans Devanagari for Hindi and a complementary Latin sans-serif with measured line height; provide sensible fallback fonts if external font loading fails. Test search across both title/description fields with parameterized, escaped query input and database collation suited to Unicode; do not assume Latin tokenization works for Hindi. Keep URLs stable and locale-neutral unless a later SEO decision requires locale-prefixed routes. Translate validation errors, navigation, statuses, buttons, empty states, and notifications rather than translating only the homepage.
