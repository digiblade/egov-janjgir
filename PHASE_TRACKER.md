## Phase 2 Prerequisites

1. Use `/opt/homebrew/opt/php@8.3/bin/php` for PHP 8.3.36; scaffold dependencies are installed.
2. User-side MariaDB is running and the local app renders DB-backed empty states. The agent shell cannot connect to `127.0.0.1:3306` (`Operation not permitted`), so if any migration is pending, run `php artisan migrate` from the user's terminal after setting `DB_PASSWORD` in `.env`.
3. Spatie Permission 7 is now in `composer.json`, `composer.lock`, and `vendor/`; its config and migration are published. From the user's terminal, run `php artisan migrate` and `php artisan db:seed --class="Database\\Seeders\\RolePermissionSeeder"` to apply the complete current schema and permission catalog. The agent shell cannot verify MariaDB migration state due to TCP sandbox restrictions.
4. Configure a fresh 32-byte random `APP_SETUP_KEY` as 64 hexadecimal characters in the private server environment before visiting `/admin/initialize`. The endpoint locks permanently after successful setup; remove the key afterward.
5. Repair Node/npm in the user's terminal, run `npm install` to create the missing `package-lock.json`, then `npm run dev` for local work or `npm run build` before deployment. The agent shell Node cannot load Homebrew's `simdjson.26.dylib`; current `public/build/manifest.json` is absent. The release script now fails fast until both lockfile and manifest exist.
6. After the Node repair/build, run `./scripts/package-release.sh [version]` from the repo root. The agent only checked `bash -n`; did not run production Composer staging, create, or inspect a ZIP.

Admin validation summaries now receive focus after a failed response, and shared field wrappers associate inline errors through `aria-describedby`/`aria-invalid` on page load. A source audit localized public dates and gallery alt fallback. Non-shared/specialized admin controls may still need field-specific error associations; screen-reader and keyboard acceptance remain unverified. HostingRaja PHP extensions/version, MariaDB version, upload/runtime limits, document root, cron, SSL, and backup details remain to be confirmed against the hosting account before deployment.
